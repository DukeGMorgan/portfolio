01

Clinical informatics / AI-assisted analysis

Make a 600+ table clinical database easier to understand.

A schema assistant turns an unfamiliar data model into a more usable starting point for investigation.

The problem

Troubleshooting an EMR requires knowing how its data fits together. With more than 600 tables, learning the schema becomes part of every investigation and a major hurdle for new analysts.

What I built

I built an AI-assisted query tool grounded in the clinical SQL Server schema. Its scope is schema and metadata: it helps with the structure of an investigation while keeping patient records outside the assistant.

What changed

Analysts have assistance navigating the data model and developing queries. The tool supports faster root-cause analysis and a shorter learning curve for people joining the team.

  2. 02Schema & metadata context
  3. 03AI-assisted query development
  4. 04Analyst validation

02

Clinical AI / Governance and architecture

Give clinical AI a controlled place to run.

The data boundary is an architectural decision that every agent has to respect.

The problem

Using AI in healthcare means knowing which tasks involve patient information, which tools can receive it, and what access each agent actually needs. A useful capability needs an approved path into the environment.

What I built

I built the enterprise AI business case and established a BAA-governed Azure AI Foundry pathway. I architected a model gateway with role-scoped agents and routing by data classification: PHI work uses BAA-covered or local inference; commercial-model work is limited to schema, code, and architecture.

What changed

Clinical and operational AI work has defined execution paths and access boundaries. The architecture provides a foundation for introducing additional workflows within those controls.

  1. 01Classify the work
  2. 02Check its data sensitivity
  3. 03Route to the permitted environment
  4. 04Scope agent access
  • AI strategy
  • Model routing
  • Local inference
  • PHI controls

Workflow automation / Administrative work

Turn a conversation into structured intake.

Project, task, knowledge base, and change requests no longer have to begin with the same manual routine.

What changed

Creating a record can start with a conversation. Reusable skills handle the intake steps that previously required manual entry and attachment, across several recurring administrative workflows.

04

Agent systems / Persistent knowledge

Stop rebuilding context every time work resumes.

Give the next session access to what the last one learned.

The problem

Agents working in isolated sessions repeatedly need the same decisions, prior findings, and procedural context. Useful work gets harder to carry forward when that knowledge remains trapped in individual conversations.

What I built

I built a shared, persistent knowledge base for specialized agents. A session review pipeline identifies recurring manual work and turns those patterns into reusable skills that other agents can use.

What changed

Decisions and findings carry across sessions. Repeated procedures can become shared automation, extending the system from the work the agents are already doing.

  1. 01Complete a task
  2. 02Review the session
  3. 03Preserve findings & reusable steps
  4. 04Use them in the next task

05

Software delivery / Cross-model collaboration

Build review into the agent workflow.

One model builds the work. Another reviews it before completion.

The problem

When one agent both creates and approves its own work, review can repeat the same assumptions that shaped the implementation. Separate model sessions also make it harder to share context and hand off a task.

What I built

I built a collaboration layer where agents from different model families share task context, challenge proposals, and hand work to one another. A cross-model review gate requires independent review before work is marked complete.

What changed

Review becomes part of the delivery process. Model selection can vary by task, and completed work has to pass another model’s assessment before moving forward.

  1. 01Shared task context
  2. 02Implementation by one model
  3. 03Review by another model
  4. 04Resolve findings before completion

  • Review gates

03 / Supporting engineering

Problems solved in clinical systems.

My experience shows up in the problems I investigate and the tools I build. These examples from my clinical systems work connect the underlying fault to a practical solution.

Clinical record access

Bring four legacy EMRs into one view.

Problem: Records were spread across four legacy platforms, with shared credentials for access.

Solution: I built a read-only clinical viewer and migration tooling with .NET, React, and Azure. The migration covered 3M+ clinical records, 770K+ documents, and 80K+ treatment cycles. Entra ID single sign-on replaced shared credentials, with authorization controls across clinics.

Safer operational changes

Check the system before applying the plan.

Problem: The live system could change between approval and execution.

Solution: My Python/Flask administration console handles chart merges, provisioning, drug libraries, and permissions. It re-validates live state before execution and stops when conditions differ from the approved plan. It caught a real divergence on its first run.

Data integrity

Find the fault behind a successful load.

Problem: A laboratory migration reported success while a non-unique key collapsed distinct records.

Solution: I traced the fault, changed the keying approach, and recovered records that would otherwise have been lost.

EMR troubleshooting

Find charts the system made invisible.

Problem: A vendor function made affected charts impossible to open and invisible in search, making missing records harder to recognize.

Solution: I traced the issue to a null-dereference and produced a reversible fix.

Permission governance

Verify the audit trail behind access changes.

Problem: During access remediation across two production sites, partial permission changes were missing from the vendor’s audit trail.

Solution: I identified the stored-procedure gap, removed excess access, and validated the governed change.

Patient document access

Put access controls around sensitive documents.

Problem: A patient document store allowed public reads, and a separate authorization gap permitted access across clinics.

Solution: I implemented authenticated document delivery, row-level controls, and a global authorization filter.
